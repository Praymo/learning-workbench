# 从一次练习到下一次练习

## 问题

题库越大不一定越容易用。学习者需要的是一组适合当前目标的题，以及做完以后能解释的反馈。维护者则需要知道题源是否可信、解析是否完整、识别结果是否可发布。

## 把问题落到输入和规则

| 决定 | 输入与实现 | 怎么检查 |
| --- | --- | --- |
| 按目的组卷 | 范围、强度、知识点、时间；`practiceSelection.ts` 控制重复与难度配额 | 固定候选题，检查重复排除、基础比例和末段难题比例 |
| 审核后才进入练习 | `practice.ts` 查询已发布且答案解析完整的题 | 检查候选门槛和题源匹配，不把缺口悄悄补成未经审核的题 |
| 评分前确认 | 上传后进入可编辑答案页；未配视觉模型时人工录入 | 用无照片演示走通确认和本地评分 |
| 不确定时留给人 | `objectiveGrading.ts` 返回待复核，评分点必须有证据 | 不支持表达不能直接判错；缺证据不能自动给过程分 |
| 掌握需要多次证据 | `studentEvidence.ts` 和 `wrongQuestionState.ts` | 检查首次错误、再次错误、连续两次正确的状态变化 |

## 页面背后的状态

练习单和作答分开保存，确认后的答案才参与评分。测试模式能走同一条评分链，但不写学习证据。这样检查流程时不会污染掌握度和错题队列。

客观题优先用本地规则。模型接入保留在识别、解答草稿和评分点建议等需要处理非结构化内容的位置，结果仍要审核。模型调用缓存按任务、Prompt 版本和输入哈希区分，避免把不同任务的旧结果混在一起。

## 验证的范围

39 项测试覆盖课程范围、数学渲染、题目指纹、选题、客观题等价判断、评分点证据和错题状态。测试通过说明这些规则在给定案例下按预期执行，不说明 OCR 准确率、真实阅卷质量或学生成绩提升。

公开副本用合成题库实走了生成练习、人工输入、确认和测试评分。下一步适合收集的是流程错误：选题为什么不合适、哪些表达进入待复核、人工修改了哪些判断。先找到问题集，再调规则。
